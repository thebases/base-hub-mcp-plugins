# Connecting a client to Base HUB MCP

If the user is asking *how to connect* rather than asking you to do something with an already-connected instance, point them at the right path for their client rather than trying to configure it yourself (you can't add a connector to your own session).

**Auth and tenant (all clients).** Every credential below is entered by the user into their own client and is sent only to their own Base HUB server; values shown are placeholders. Endpoint `https://<host>/mcp`. The only credential is an OAuth 2.0 bearer token: `Authorization: Bearer YOUR_ACCESS_TOKEN`. `X-API-Key` never authenticates `/mcp` (it is only an opt-in `app.supportApikey` path on `/rpc`), and the old per-user `mcp_api_key` no longer exists. Get a token from `POST /oauth/token` (form body or flat JSON body with the same keys: `grant_type`, `username`, `password`, `db`, `refresh_token`, `client_id`, `client_secret`, `code`, `redirect_uri`, `code_verifier`): `grant_type=password` for a person's login (the person types their own Base HUB login into their own client; never read it from files or the environment), `grant_type=client_credentials` for a registered `sys.oauth_client` service caller (create one via `auth.record.create`; the secret is shown once). Tenant database: `?db=<name>` or `X-Database-Name`; the token's `db` claim must match it (401 `oauth token is not valid for the requested database` otherwise). Tokens expire; mint a new one on 401 `invalid bearer token`.

**Discovery and registration.** The server publishes `/.well-known/oauth-protected-resource` (and `/.well-known/oauth-protected-resource/mcp`), `/.well-known/oauth-authorization-server`, answers `/mcp` 401s with a `WWW-Authenticate` pointer to that metadata, and accepts dynamic client registration at `POST /oauth/register` (public PKCE clients allowed). So an OAuth-capable MCP client only needs the URL: it registers itself and opens the Base HUB login page. Registration only accepts these redirect URIs: Claude's two `/api/mcp/auth_callback` URLs, `https://chatgpt.com/connector_platform_oauth_redirect`, and loopback `http` (CLIs); an admin can change the list with `server.oauthDcrRedirectUris` or turn registration off with `server.oauthDcrDisabled`. Users who prefer a fixed client id/secret get one from **Get MCP token** in the account menu.

**Tenant caveat.** Claude and ChatGPT send no `db` on registration or token exchange, so they land in the home database. For another tenant, put a proxy in front that adds `X-Database-Name: <db>`. Clients that let you set headers (Codex, Gemini CLI, Claude Code) can send `X-Database-Name` themselves. Every proxy location serving `/oauth/*` and `/.well-known/oauth-*` must pass the original `Host` header, or Claude rejects the sign-in ("couldn't confirm the identity of the sign-in service").

| Client | How to attach Base HUB |
|---|---|
| **Claude (claude.ai, Desktop, mobile)** | Settings → Connectors → Add custom connector, URL `https://<host>/mcp`. Leave the OAuth client fields empty (dynamic registration), or open Advanced and paste the id/secret from Get MCP token. Enable it per chat in the tools menu. Skills: upload this folder as a skill, or paste `references/chat-instructions.md` into a Project. |
| **Claude Code** | `claude mcp add --transport http base-hub https://<host>/mcp`, then `/mcp` to sign in. With a token instead: add `--header "Authorization: Bearer YOUR_ACCESS_TOKEN"` (and `--header "X-Database-Name: YOUR_DB"`). |
| **ChatGPT (web/desktop)** | Needs a plan/workspace that allows custom MCP apps (developer mode). Settings → Apps & Connectors → create an app with URL `https://<host>/mcp`, authentication OAuth; it registers itself and uses the stable `connector_platform_oauth_redirect` callback. GPT instructions alone never grant access: attach the app, then paste `references/chat-instructions.md` into the GPT or Project instructions. GPT **Actions** (OpenAPI, manual OAuth URLs) is a separate, older path: see the user guide. |
| **OpenAI Codex (CLI, IDE)** | `~/.codex/config.toml`: `[mcp_servers.base-hub]` with `url = "https://<host>/mcp"`, then either `codex mcp login base-hub` (OAuth) or `bearer_token_env_var = "BASE_HUB_TOKEN"` for a token from `/oauth/token`. Codex reads this skill from `.agents/skills/`. Codex inside a ChatGPT workspace needs the workspace app enabled for the user's role. |
| **Gemini CLI** | `.gemini/settings.json` → `mcpServers.base-hub.httpUrl = "https://<host>/mcp"`. Without `headers` it discovers OAuth and signs in through `http://localhost:7777/oauth/callback` (`/mcp auth base-hub`); or set `headers: {"Authorization": "Bearer YOUR_ACCESS_TOKEN", "X-Database-Name": "YOUR_DB"}`. Restart, check with `/mcp`. Gemini CLI reads this skill from `.agents/skills/` or `.gemini/skills/`. |
| **Gemini app / Gems** | No custom MCP server support for general users at the time of writing, so it cannot operate Base HUB. Use Gemini CLI; a Gem can only hold `references/chat-instructions.md` as guidance. |
| **APIs (Claude Messages MCP connector, OpenAI Responses `mcp` tool, Gemini SDK MCP sessions)** | Pass `https://<host>/mcp` and an `Authorization: Bearer YOUR_ACCESS_TOKEN` header; mint the token server-side with `grant_type=client_credentials` for a `sys.oauth_client`. |

- **stdio-only clients**: download the bridge from `GET /mcp/bridge` (`base-hub-mcp-bridge.js`, Node 18+); env `BASE_HUB_URL`, `BASE_HUB_MCP_KEY` (the bearer token) and optional `BASE_HUB_DB_NAME`.
- Transport: Streamable HTTP, single JSON responses only (`GET /mcp` → 405), `Accept` must be absent or allow `application/json`, `Mcp-Session-Id` issued on `initialize` (optional to send back; 30 min sliding; `DELETE /mcp` ends it), `MCP-Protocol-Version` must be `2025-06-18` if sent. Other routes: `GET /mcp/health` (no auth), `GET /mcp/tools` (bearer, same catalog as `tools/list`).

Full step-by-step per client, the raw JSON-RPC shape (`initialize` / `tools/list` / `tools/call`) and a GPT-Actions-compatible OpenAPI schema for `/mcp`, are in the in-app user guide's "Choose Your AI Client" section (`user_guide/base-mcp-user-guide.md` (read it with `knowledge.doc.read`)): pull it in only for first-time client setup, not routine data work.
